# AgentYard — руководство

Как запускать, что где лежит после прогона и как устроен код. Короткое описание — в [README.ru.md](../README.ru.md), движок — в [ENGINE.md](ENGINE.md), декомпозиция и конвейер — в [ALGORITHM.md](ALGORITHM.md).

## Что нужно на компьютере

| Что | Зачем | Как проверить |
| --- | --- | --- |
| Node.js 22.6 или новее | Запускает TypeScript напрямую, без сборки | `node -v` |
| git | Ветки прогонов, рабочие копии задач, откат | `git --version` |
| Ollama | Запускает модели | `ollama -v` |

Сторонних пакетов для работы нет. Все команды идут через `ay.bat`: он запускает Node с флагом `--experimental-strip-types`, который нужен версиям до 22.18.

## Интерфейс

| Файл | Что делает |
| --- | --- |
| `start-app.bat` | Отдельное окно приложения (Electron). При первом запуске ставит Electron через `npm install`, около 100 МБ. Выбирает папку диалогом, сохраняет отчёт в PDF одной кнопкой. |
| `start-ui.bat` | То же в браузере, без Electron. PDF — через печать отчёта. Окно консоли не закрывать: это сервер. |

Разделы:

- **Новая задача** — папка проекта, цель обычными словами, проверка готовности проекта, настройки прогона.
- **Ход работы** — план на утверждение; этапы и задачи с номерами (2.1.3); какая модель что делает сейчас; журнал. По щелчку на задачу — бриф, файлы, признаки готовности, переписка с моделью. У застрявшей задачи — блок «На чём споткнулись» и поле для подсказки. «Стоп» останавливает прогон сразу.
- **История** — прошлые прогоны: применён ли результат, «Применить» / «Откатить», журнал и отчёт.
- **Модели** — видеокарта, память, состояние Ollama, бригада; каталог с оценкой «влезет / часть в оперативке / не влезет» и кнопкой «Скачать».
- **Подключения** — GitHub, GitLab, Jira, Trello, YouTrack. Токены хранятся только у тебя в `~/.agentyard/integrations.json`, моделям они не видны. «Взять в работу» подставляет задачу как цель. После прогона можно отправить ветку и открыть PR/MR и записать итог в задачу.

Как устроено: `src/server.ts` поднимает сервер только на `127.0.0.1` со случайным токеном в адресе. Без токена API не отвечает, чужие имена хостов отклоняются. Интерфейс в `ui/` — HTML, CSS и JS без сборки и библиотек. Живые события идут через Server-Sent Events. Electron (`electron/main.cjs`) запускает этот сервер обычным Node и показывает его в окне; ядро от Electron не зависит. Из командной строки интерфейс открывается командой `ay ui`.

## Командная строка

```bat
ay hw                     :: железо и тир
ay models                 :: что влезет в видеокарту
ay models pull qwen3.6    :: скачать модель
ay run --repo C:\путь\к\проекту --goal "добавь экспорт отчёта в CSV и покрой тестами"
ay resume <папка> <id>    :: продолжить прерванный прогон
ay apply <папка> <id>     :: применить результат в проект (undo — откатить)
ay eval                   :: экзамен на небрежных просьбах
```

Основная ветка не трогается: изменения ложатся в ветку `agentyard/run-<время>`.

| Опция `ay run` | Что делает |
| --- | --- |
| `--goal fix-tests` | Починить падающие тесты; план строится без модели |
| `--plan план.json` | Взять готовый план вместо планировщика |
| `--no-review` | Без ревью моделью |
| `--offload` | Разрешить модели частично жить в оперативке: медленнее, зато влезают модели крупнее |
| `--ctx 32768` | Длина контекста; по умолчанию 16 384 токена |
| `--init-git` | Если папка не под git — создать репозиторий, чтобы был откат |
| `--allow-install` | Разрешить ставить пакеты из плана |
| `--yes` | Не спрашивать подтверждение плана |

## От небрежной просьбы до результата

1. **Где это в коде.** До планирования программа без модели ищет по словам цели: «кнопки красными» → `btn`, `button`, `red`, `color` → нужный CSS-файл (`src/context.ts`).
2. **План по этапам.** Планировщик пишет, как понял цель, делит работу на 3–5 этапов и маленькие задачи. Одинаковые задачи склеиваются (`src/plan.ts`).
3. **Проверки своей части проекта.** В монорепо каждая задача проверяется командами той части, где лежат её файлы. Если проверка была красной до прогона, задача отвечает только за новые падения (`src/engine/workspace.ts`, `src/engine/baseline.ts`).
4. **Разбор неудачи.** Своя ошибка, задела соседей, окружение, формат ответа, сбой Ollama. Нет пакета — программа ставит сам пакет и не тратит попытку. Модель повторяет ту же правку — сразу второе мнение (`src/engine/triage.ts`, `src/engine/policy.ts`).
5. **Застряла — подскажи.** В панели задачи видно, на какой проверке остановились, ошибки с файлом и строкой, что уже пробовали. Вставляешь кусок кода или пару слов — исполнитель делает следующую попытку с подсказкой (`src/engine/stumble.ts`). Можно и доделать руками: «Открыть в редакторе» правит отдельную копию прогона, после сохранения программа сама проверяет правку и продолжает (`src/handoff.ts`). Свой редактор задаётся переменной `AGENTYARD_EDITOR`.
6. **Правка по образцу.** Одинаковая правка в однотипных файлах — одна задача: модель правит один файл, программа повторяет правку во всех остальных с подстановкой имени сущности (`src/replicate.ts`, `src/rules.ts`).
7. **Установка пакетов.** Нужная библиотека видна в плане перед запуском. Пакет ставится с `--no-save`, зависимость дописывается в `package.json` в ветке прогона, после применения выполняется `npm install` (`src/install.ts`).
8. **Приёмка по цели.** Когда задачи готовы, модель сверяет итог с целью и при необходимости ставит задачи на доработку, до двух кругов (`src/goalcheck.ts`).
9. **Сразу в проект.** Если всё сделано без человека, ветка прогона вливается в текущую ветку. Незакоммиченные правки в тех же файлах программа не затирает: откажет и назовёт файлы (`src/apply.ts`).
10. **Продолжение после сбоя.** Состояние пишется в `state.json` при каждом изменении. Закрылось окно — в «Истории» появляется «Продолжить».

## Не только код

Сводка документа, разбор таблицы, парсинг: проекту не нужны ни `package.json`, ни git — репозиторий для отката создаётся сам. Программа читает docx, xlsx, pptx, odt, html, rtf, csv, json и PDF с текстом (`src/engine/extract.ts`). Большой файл режется на части, части сводятся в итог (`out/.parts/`). Результат кладётся в `out/` и проверяется по формату: пустой файл, разное число колонок в CSV, битый JSONL.

## Языки и стеки

Стек и команды проверки находятся сами: Node/TypeScript, Python (pytest, mypy, ruff, Django check), Go (go vet, go test), Rust (cargo), Java/Kotlin (Maven/Gradle), .NET, PHP (phpunit, phpstan), Ruby (rspec), а также монорепо (`src/stacks.ts`). Рецепты типовых задач лежат в `skills/recipes/`: эндпоинт, миграция, UI-кит, тёмная тема, docker-compose, i18n и другие. Они подбираются по цели и стеку. Свой рецепт — новый `.md`-файл: строка `триггер: <регулярка>`, строка `проект: <регулярка по пакетам>`, `---`, текст.

## Экзамен: `run-eval.bat` (или `ay eval`)

Небрежные просьбы на учебных проектах. Результат проверяет программа по файлам, а не модель:

| Сценарий | Просьба | Как проверяется |
| --- | --- | --- |
| web-red-buttons | «сделай кнопки красными» | цвет основной кнопки в CSS — красный |
| web-sticky-header | «чтоб шапка у таблиц не уезжала» | `position: sticky` у `th`/`thead` |
| web-dark-theme | «ночью глаза режет, сделай тёмную тему» | тёмный фон и светлый текст в `prefers-color-scheme: dark` |
| web-title | «на странице адресов заголовок — Адреса доставки» | `<h1>` на нужной странице, другие не тронуты |
| web-rename-everywhere | «везде где кнопка Добавить пусть будет Создать» | «Создать» на всех страницах, «Добавить» нигде |
| web-docker-port | «в докере порт 8080 а не 3000» | `EXPOSE 8080`, `PORT=8080`, 3000 нигде |
| web-ui-kit | «натяни популярную юай библиотеку» | UI-кит в зависимостях и импортируется на страницах |
| shop-promo | промокоды небрежным текстом | скрытые тесты против `src/promo.js` |
| demo-fix | «тесты падают почини» | `node --test` зелёный |

Итог — «сдано X из N» и отчёт `eval-runs\<время>\eval.md`. Часть сценариев: `ay eval --only web-red-buttons,web-title`.

## Где смотреть результат прогона

В папке проекта появляется `.agentyard\runs\<время>\`; в git она не попадает.

| Файл | Что внутри |
| --- | --- |
| `journal.txt` | Журнал: кто что делал и почему, по строке на событие |
| `events.jsonl` | Те же события для программ |
| `report.html` / `report.md` | Отчёт; раздел «Куда ушло время» |
| `transcripts\` | Полные переписки с моделями |
| `state.json` | Состояние для продолжения после сбоя |

Статистика моделей копится в `%USERPROFILE%\.agentyard\stats.json`: так программа узнаёт, какая модель с чем справляется на твоём железе.

## Для разработки самого AgentYard

- `npm test` — 178 тестов, учебная модель, Ollama не нужна. Тест монорепо с Go пропускается, если Go не установлен.
- `npm run typecheck` — проверка типов (нужен `npm install` ради TypeScript).
- Интерфейс с учебной моделью: добавь `?mock` к адресу страницы.
- `run-demo.bat` — учебный проект с двумя ошибками на учебной модели; `run-ollama-demo.bat` — тот же проект на настоящих моделях.

## Ограничения

- Один прогон за раз, одна видеокарта.
- План можно утвердить или отклонить, но не отредактировать по задачам.
- Статистика в JSON, а не в базе.
- Поиск по коду и карта проекта сделаны простыми средствами, без ripgrep и tree-sitter.
- MCP-инструменты для агентов пока не подключены.
